# تقرير مراجعة الأمان — Franc Warak 1.0.11

**التاريخ:** 28 أكتوبر 2026
**النطاق:** مراجعة ساكنة لمصدر React/TypeScript وطبقة التخزين والتصدير وقواعد Firebase الموجودة في المستودع، مع اختبار واجهة محلي. لم يُجرَ اختبار اختراق أو فحص لخدمات الإنتاج.

## النتيجة المختصرة

لم يظهر في الفحص الساكن استخدام مباشر لـ`innerHTML` أو `dangerouslySetInnerHTML` أو `eval`، ولم تُكتشف بصمات مفاتيح خاصة أو رموز وصول شائعة في الملفات المتتبعة وقت الفحص. أُضيفت معالجة لحقن صيغ CSV، ونُقل الحوار إلى طبقة مستقلة مع سطح معتم وحدود تمرير. اجتاز TypeScript والبناء المحلي لـAndroid وفحوصات CSV واختبار الواجهة المحلي.

## تغييرات الحماية في 1.0.11

- تُحيّد خلايا CSV التي يبدأ نصها، حتى بعد محارف فراغ/تحكم، بـ`=`, `+`, `-` أو `@` بإضافة بادئة نصية، وتُضاعف علامات الاقتباس وتُسطّح أسطر النص. اختُبر ذلك بعشر حالات تشمل صيغاً محتملة، علامات اقتباس، أسطر جديدة وأرقاماً سالبة.
- أُضيف تنبيه داخل شاشة الدردشة يوضح أن الغرفة عامة وأن اسم المزارع والرسائل يراها مستخدمو التطبيق، وينصح بعدم إرسال الهاتف أو البيانات الشخصية والمالية.
- لا تتغير بيانات المبيعات والمصاريف والأجور أو قواعد صلاحيات Firebase ضمن هذا الإصدار؛ لم يُنفّذ أي مسح أو كتابة لقاعدة الإنتاج.

## نقاط تستلزم معرفة المستخدم

1. **الدردشة عامة عمداً:** في `database.rules.json` يسمح المسار `publicChat/messages` بالقراءة لأي مستخدم مسجّل دخول Firebase (`auth != null`). التطبيق يستخدم دخولاً مجهولاً؛ لذلك لا تُعد هوية المرسل المجهولة تحققاً قوياً من شخصه، والرسائل والأسماء ليست خاصة. أُبقي السلوك كما هو لأنه يطابق تصميم الغرفة العامة المطلوب. لم أتحقق من أن القواعد المنشورة في Firebase تطابق الملف المحلي.
2. **التخزين والنسخ الاحتياطية:** تبقى بيانات الموسم في `localStorage` وملفات JSON/CSV المصدّرة غير مشفّرة على مستوى التطبيق. على Android تكون ملفات التطبيق ضمن عزل النظام، لكن النسخة التي يصدّرها المستخدم لا تظل محمية بذلك العزل بعد حفظها أو مشاركتها. احفظ النسخ في مكان موثوق ومقفل، ولا تشاركها علناً.
3. **تدقيق الاعتماديات:** أظهر `npm audit` أربعة تنبيهات **منخفضة فقط**، ولا توجد تنبيهات متوسطة أو عالية أو حرجة. سلسلة الاعتماديات تمر عبر `vite-plugin-pwa@2.0.0` و`workbox-build` و`@rollup/plugin-node-resolve` إلى `deepmerge@4.3.1`، وتشمل التحذير GHSA-gcqx-w48m-w2h4 الخاص بتسميم النماذج الأولية. أداة التدقيق تعرض حلاً يتطلب تغييراً رئيسياً/تبديل إصدار `vite-plugin-pwa`؛ لم أنفّذ إصلاحاً قسرياً أو خفضاً لإصدار أداة البناء دون تحقق توافق مستقل، لأن ذلك قد يكسر توليد Service Worker. أوصي بمعالجة هذا البند في تحديث اعتماديات منفصل مع فحص بناء PWA.

## التحقق المنفذ

- `npm run lint` — ناجح.
- `npm run android:debug` — ناجح؛ APK قابل للقراءة ورقم الحزمة `com.jonbander.francwarak`، `versionName=1.0.11` و`versionCode=12`.
- اختبار Chromium محلي على مساحة `390×620`: تفضيل الثيم بقي بعد إعادة التحميل؛ سطوح البيع والورشة معتمة؛ جذر الحوار أعلى من شريط التنقل (`z-index:100` مقابل `40`)؛ وأمكن تمرير نموذج البيع مع بقاء زر «إلغاء» ضمن حدود الحوار. حُجبت اتصالات Firebase الخارجية خلال اختبار الواجهة.
- نسخة CSS الفاتحة المحفوظة طابقت ملف CSS في commit الإصدار 1.0.6.
- فحص توقيعات أسرار شائعة في ملفات Git، مع فحص `git diff --check`.

## حدود التقرير

هذه مراجعة ساكنة واختبارات بناء/واجهة محلية وليست ضماناً أمنياً أو اختبار اختراق. لم أختبر قاعدة Firebase المنشورة أو WordPress الحي، ولم أجرِ فحص Strix أو إرسال رسائل إلى مستخدمين حقيقيين. كما أن APK الناتج Debug للاختبار، وليس إصداراً Release موقّعاً بمفتاح دائم.
